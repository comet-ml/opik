Image evidence reaches both the evaluated agent and the optimizer as native content blocks.
Configure their models independently: `ChatPrompt.model` runs the task; the optimizer's `model`
improves its instructions. HRPO uses its independently configured `reasoning_model` for analysis.
No model or model parameters are borrowed from the other role.

## Configure image optimization

```python wordWrap
from opik_optimizer import ChatPrompt, MetaPromptOptimizer

prompt = ChatPrompt(
    messages=[
        {"role": "system", "content": "Read the image and answer the question."},
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "Question: {question}"},
                {"type": "image_url", "image_url": {"url": "{image}", "detail": "low"}},
            ],
        },
    ],
    model="openai/gpt-4o-mini",
    model_parameters={},
)
optimizer = MetaPromptOptimizer(model="openai/gpt-4o")  # must support vision
```

Dataset rows supply `question` and `image`. The image value may be an HTTPS URL or an image data
URL. Keep remote URLs valid for the full optimization run. A data URL remains inside an
`image_url` block; it is never expanded into the textual prompt description.

## What the optimizer sees and edits

Each optimizer chooses the training cases it shows its model, always from the training dataset:
MetaPrompt shows `num_task_examples` items, HRPO each failure-analysis batch (`batch_size`), GEPA
its reflection minibatch, and FewShot the items it builds its template from. Evolutionary reasons
about prompts only. Each case is rendered once, with its image blocks next to its case ID,
rendered input, output, scores and, for HRPO, the agent's recorded steps and the images it saw.

The optimizer returns edits addressed to existing text segments. For example, `message:1:part:0`
identifies the first text block in the second message. Media, message roles, tool callables,
unselected text blocks and agent model settings remain unchanged. Duplicate, unknown or
non-editable targets and edits that remove template variables are rejected.

Image cost depends on the number, size and detail of images in those cases; the settings above
control how many cases each request carries. Image evidence requires a vision-capable optimizer
model; an unsupported model fails the run before any evaluation. For custom model aliases or
deployments, register their vision capability in LiteLLM before the run.

## Optimizer support

| Optimizer | Image evidence for reasoning | How edits are applied |
|---|---|---|
| MetaPrompt | Native blocks with its `num_task_examples` training cases | Targeted text edits for each prompt or bundle member |
| HRPO | Native images for every case in each analysis batch, including recorded agent images | Targeted text edits and selected tool descriptions |
| Evolutionary | Images in the prompt template; no dataset cases | Targeted edits of each original parent/template |
| FewShot Bayesian | Native images in template generation | Text edits select the example placeholder; image demonstrations are inserted before the current task |
| GEPA | Native images from its reflection batch; requires `gepa>=0.1.4` | Individual text-block and tool-description components |
| ParameterOptimizer | Makes no reasoning calls | Changes only explicitly searched model parameters; forwards media during evaluation |

FewShot image demonstrations keep their images as native blocks. The current task's input and
media remain the final user message.

Native optimizer evidence supports **images**. Audio, video and file blocks are named in the
optimizer's context but not sent. Evaluation support for those modalities depends on the agent
and its model.

## Validate your run

Use metrics that assess the task output and return useful reasons. Inspect cases with their
images and scores in Opik. Confirm that the winning prompt retains the original image
placeholders and the intended agent model configuration.

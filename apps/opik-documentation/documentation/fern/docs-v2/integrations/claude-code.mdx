Opik works with [Claude Code](https://claude.ai/code) in two ways:

- **Tracing:** Claude Code's native OpenTelemetry export sends each session to Opik as a trace, so
  you can review what developers asked, what the model answered, which tools ran and what each
  turn cost.
- **MCP tools and skills:** the Opik connector or the Opik plugin gives Claude Code the Opik MCP
  server tools and the Opik skills, so it can instrument your app, read and score traces, run
  evaluations and explain failures in your Opik workspace.

The two are independent, and you can use either or both.

<Tip title="Looking to reduce Claude Code spend rather than review sessions?">
  Opik shows you **what Claude Code did**. If the question is **where the tokens went and how to
  spend fewer of them**, that is [Cost Intelligence](/cost-intelligence/overview): every Claude
  Code API call captured on the wire and attributed to system prompt, tool schemas, MCP servers,
  skills, memory and user input, per user and per repository, with policy controls that typically
  cut spend by 15% to 30%. Only counts and metadata leave the machine, never content. Claude Code
  is Cost Intelligence's primary agent.
</Tip>

## Trace Claude Code sessions with OpenTelemetry

Claude Code can emit OTel **metrics**, **events** and, in beta, **trace spans**. Opik ingests the
trace spans only.

<Warning>
  Without `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1` Claude Code sends only metrics and events, and
  nothing appears in Opik. Prompt, tool I/O and assistant output are **redacted by default**; the
  flags in this section un-redact them. Assistant output on spans additionally requires the detailed-tracing
  beta, which is available for the Claude Agent SDK and non-interactive `claude -p` runs but gated
  in interactive sessions.
</Warning>

Set these before starting Claude Code (Opik Cloud shown; swap the endpoint for your deployment,
see the [Opik OpenTelemetry overview](/integrations/opentelemetry)):

```bash wordWrap
# 1. Enable telemetry and trace-span emission
export CLAUDE_CODE_ENABLE_TELEMETRY=1
export CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1

# 2. Export traces to Opik
export OTEL_TRACES_EXPORTER=otlp
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=https://www.comet.com/opik/api/v1/private/otel
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=<your-api-key>,Comet-Workspace=<your-workspace>,projectName=<your-project-name>'

# 3. Un-redact prompt and tool input/output
export OTEL_LOG_USER_PROMPTS=1
export OTEL_LOG_TOOL_DETAILS=1
export OTEL_LOG_TOOL_CONTENT=1

# 4. Assistant output on spans (detailed-tracing beta, non-interactive only)
export ENABLE_BETA_TRACING_DETAILED=1
export BETA_TRACING_ENDPOINT=https://www.comet.com/opik/api/v1/private/otel
```

Spans arrive as `claude_code.interaction` (one per prompt) with nested `claude_code.llm_request`
and `claude_code.tool` spans. Opik maps their content to trace and span input/output and
calculates cost from the model and token attributes.

For the full variable reference, endpoint modes and validation steps, see
[Claude Agent SDK and Claude Code OpenTelemetry](/integrations/claude-agent-sdk).

### Validation

1. Run a short Claude Code turn that uses a tool, for example "list the files in this directory".
2. Open the project in Opik that you set as `projectName`.
3. Confirm the trace carries content: the trace is named `claude_code.interaction`, its input is
   your prompt, and the model's response is on the `claude_code.llm_request` spans (with model,
   tokens and cost). The trace-level output stays empty. Tool calls appear as `claude_code.tool`
   spans with their input and result.

## Opik MCP tools and skills

The hosted [Opik MCP server](/mcp-server) and the Opik skills let Claude Code work in your Opik
workspace. They do not log Claude Code sessions to Opik. For that, use
[OpenTelemetry export](#trace-claude-code-sessions-with-opentelemetry).

There are two ways to add them:

- **The Opik connector (recommended):** the Opik MCP server from the Claude connector directory.
  It adds the MCP tools.
- **The Opik plugin:** installs the Opik skills and registers the hosted MCP server.

### Add the Opik connector (recommended)

<Note>
  The Opik connector works with Opik Cloud only. For a self-hosted or open-source Opik, see
  [Self-hosted Opik](#self-hosted-opik).
</Note>

1. In claude.ai, open **Settings** → **Connectors**, find **Opik** and connect it.
2. Sign in to Opik in the browser. The server works in the workspace that you pick when you sign
   in; there is no API key to set.
3. Sign in to Claude Code with the same claude.ai account. `/mcp` shows the server as
   `claude.ai Opik`.

The connector does not install the skills in Claude Code. Claude Code can still load a skill on
demand with the `read_skill` tool. To install the skills, use the Opik plugin.

### Install the Opik plugin

Inside Claude Code:

```
/plugin install opik --marketplace comet-ml/opik-mcp
```

On Claude Code before 2.1.275, run these two commands instead:

```
/plugin marketplace add comet-ml/opik-mcp
/plugin install opik@opik
```

Start a new session, then sign in from `/mcp` → **Authenticate**. The sign-in opens in the
browser; there is no API key to set. `/mcp` shows the server as `plugin:opik:opik-cloud`.

### Skills

The Opik plugin installs these skills. They load as `opik:<skill>`, such as
`opik:opik-instrument`. Claude Code picks the skill that fits your request.

| Skill | What it does |
| --- | --- |
| `opik` | Reference for the Opik SDK: tracing, span types, framework integrations, threads and the prompt library. |
| `opik-instrument` | Adds Opik tracing to an existing app and confirms that a real trace arrives in Opik. |
| `opik-diagnose` | Finds the traces that need attention: Diagnostics issues, errors, failed tool calls, latency and low online-evaluation scores. |
| `opik-explain` | Finds the root cause of a failure in a trace, or of a pattern across traces. |
| `opik-evaluate` | Builds an LLM evaluation, runs it against the app and returns an Opik experiment with scores. |
| `opik-compare` | Runs a candidate against the baseline on an Opik test suite and shows which cases broke and which got fixed. |
| `opik-test` | Turns a failing trace into a regression case in a test suite. |
| `opik-verify` | Decides ship or hold for a candidate against an explicit release policy. |
| `opik-online-eval` | Creates an online evaluation rule that scores production traces. |
| `opik-optimize` | Improves a prompt with the Opik Agent Optimizer and saves the winner as a new prompt version. |
| `opik-annotate` | Sets up human review: an annotation queue with a custom annotator view. |

### MCP tools

The MCP server gives Claude Code five tools. Claude Code calls them on its own; you do not call
them by hand.

| Tool | What Claude Code does with it |
| --- | --- |
| `read` | Gets one entity by id, name or `opik://` URI. |
| `list` | Lists entities, with filters, sorting and a time window. |
| `write` | Logs traces and spans, adds scores and comments, saves prompt versions, and manages test suites and experiments. |
| `schema` | Gets the exact payload shape for a write operation. |
| `read_skill` | Loads one of the Opik skills on demand. |

For the full list of operations, see the [MCP tools reference](/mcp-server/tools).

### Self-hosted Opik

The connector and the plugin connect to Opik Cloud. The skills work with any Opik. To use your
own server:

1. Add your server:
   - For a self-hosted Comet that serves the MCP server, run
     `claude mcp add --transport http opik-mcp https://<host>/opik/api/v1/mcp`.
   - For any other self-hosted or open-source Opik, follow the [MCP server setup](/mcp-server).
2. If you installed the plugin, disable `plugin:opik:opik-cloud` in `/mcp`.

### Update the plugin

Claude Code does not update the plugin on its own. Run `/plugin marketplace update opik`, then
`/plugin update opik@opik`, or turn on auto-update for the marketplace in `/plugin`.

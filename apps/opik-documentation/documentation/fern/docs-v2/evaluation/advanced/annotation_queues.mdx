Involving subject matter experts in AI projects is essential because they provide the domain knowledge and contextual judgment that ensures model outputs are accurate, relevant, and aligned with real-world expectations. Annotation Queues in Opik make it simple for subject matter experts (SMEs) to review and annotate agent outputs. This feature streamlines the human-in-the-loop process by providing easy queue management, simple invitation flows, and a distraction-free annotation experience designed for non-technical users.

Annotation Queues are collections of traces or threads that need human review and feedback. They enable you to organize content for review, share with SMEs easily, collect structured feedback, and track progress across all your evaluation workflows.

## Creating and Managing Annotation Queues

Each annotation queue is defined by a collection of traces or threads, evaluation instructions, and feedback definitions:

1. **Queue Configuration**: Set up the queue with clear instructions and scope
2. **Content Selection**: Add traces or threads that need human review
3. **SME Access**: Share queue links with subject matter experts for annotation

### Setting Up Your First Queue

Open your project, select **Annotation queues** in the sidebar, and click **Create queue**.

<Frame>
  <img src="/img/evaluation/create_new_annotation_queue.png" alt="The Create annotation queue form" />
</Frame>

Configure your queue with:

- **Name**: Clear identification for your queue
- **Scope**: Choose between traces or threads
- **Instructions** (optional): Provide context and guidance for reviewers
- **Feedback scores** (optional): Select the [feedback definitions](/administration/workspace-settings/feedback_definitions) SMEs will use for scoring
- **Annotators per item**: How many annotators must score an item before it counts as complete
- **Lock timeout**: How long an item stays reserved for the annotator who opened it. After this time, another annotator can pick it up
- **Automation**: Add items automatically based on their feedback scores (see [Populating a Queue Automatically](#populating-a-queue-automatically))
- **Annotator view**: What annotators see for each item (see [Customize what annotators see](#customize-what-annotators-see))

### Adding Content to Your Queue

You can add items to your queue in several ways:

**From the Traces or Threads list on the Logs page:**

- Select one or multiple items
- Click **Add to > Annotation queue**
- Choose an existing queue or create a new one

**From a single trace or thread:**

- Open the trace or thread
- Click **Add to > Annotation queue** in its toolbar
- Select your target queue

### Populating a Queue Automatically

A queue can also collect items on its own, so low-quality output reaches reviewers without anyone
watching the traces list. Turn on **Automation** when creating or editing a queue, then describe what
is worth reviewing as conditions on feedback scores:

- All conditions must hold for an item to be added — they are combined with **AND**, and you can set up
  to five
- An item with no value for a score in the condition never matches it
- Where several people have scored the same name, the conditions are matched against the average of
  their values, so a condition that holds for one reviewer's score can stop holding once another
  disagrees
- Tick **Cap automatically added items at** to bound how large automation lets the queue grow; once the
  queue holds that many items, however they got there, automation stops adding until some are removed.
  Adding by hand is never refused. Leave it unticked for no limit. Treat the number as approximate: a
  burst of scores arriving at once can carry the queue a little past it before it settles

Conditions are evaluated whenever a score is written, so an item is collected once it qualifies —
whether that is seconds after the trace, when an online evaluation rule scores it, or days later when
someone scores it by hand. The source of the score does not matter. Collection is not instant: an item
appears a few seconds after its last score, which leaves room for a run of scores to settle so a queue
is not filled on a value that is about to change.

Automation looks forward, not back. Switching it on collects nothing that has already been scored, only
what is scored from then on, so seed a queue with the work you already have by adding those items by
hand.

<Note>
  Automation never adds an item a queue has already held. If a reviewer removes an item, a later score
  will not bring it back — but you can always add it again yourself. Manual additions keep working on
  an automated queue, and the queue's items table shows how each item arrived under **Source**.
</Note>

Only traces and threads your application logged are collected — the ones that come from the SDK or the
REST API. Playground runs, experiment traces, optimization runs and traces produced by evaluators are
scored like any other, but automation skips them, so trying a prompt in the Playground never sends work
to your reviewers. Those can still be added by hand.

Automation works the same way for thread queues, matching on thread scores instead of trace scores.

<Note>
  Automation is configured in the UI. The SDK helpers below create queues without it — open the queue
  and choose **Edit** to give one conditions afterwards.
</Note>

### Sharing with Subject Matter Experts

Once your queue is set up, you can share it with SMEs:

**Copy Queue Link:**

<Tip>
  **SME Access Required**: Subject matter experts must be invited to your
  workspace before they can access annotation queues. Make sure to invite them
  to your project first, then share the queue link.
</Tip>

- Open the queue and click **Share** to copy the queue link
- Share the link directly with SMEs via email, Slack, or other communication tools

Click **Annotate** to open the queue the way your annotators see it.

## SME Annotation Experience

When SMEs open a queue link, they land on a welcome page with the queue's instructions and the feedback scores they will give.

<Frame>
  <img src="/img/evaluation/sme_instruction_page.png" alt="The welcome page of an annotation queue" />
</Frame>

They click **Start annotating** (or **Resume annotating** when they come back) and review one item at a time.

<Frame>
  <img src="/img/evaluation/sme_annotation_page.png" alt="An annotator reviewing a trace with the default view" />
</Frame>

The annotation page has three parts:

1. **Queue items**: the items still **To review** and the ones already **Processed**, so annotators can go back to an item
2. **The item**: a trace shows its input, output and metadata; a thread shows the conversation. A queue can replace this with a [custom view](#customize-what-annotators-see)
3. **Annotate**: a comment and the queue's feedback scores, each with an optional reason

**Read instructions** shows the queue's instructions again at any time.

### Annotation Workflow

1. **Access the queue**: SME clicks the shared link
2. **Review content**: Examine the trace or thread
3. **Provide feedback**: Score using the queue's feedback scores
4. **Add comments**: Optional text feedback
5. **Continue**: Click **Next** to move to the next item

When a queue asks for more than one annotator per item, each item is reserved for the annotator who opened it for
the queue's **Lock timeout**, so two people don't review the same item at once. An item counts as complete once
the number of annotators set in **Annotators per item** have scored it.

## Customize what annotators see

By default, annotators see a trace's input, output and metadata, or a thread as a conversation. That works for
many queues, but annotators often need the item laid out around what they judge: the plan next to the request,
the budget checked against its limit, judge scores kept out of sight until they've given their own score.

An **annotator view** replaces the default view for every item in a queue. It is a small HTML view built for the
queue's data. Scoring, comments and navigation stay the same.

<Frame>
  <img src="/img/evaluation/sme_annotation_custom_view.png" alt="An annotator reviewing a trace with a custom annotator view" />
</Frame>

### Build it with Ollie

[Ollie](/ollie) looks at the queue's items (or the project's latest traces when the queue is empty), proposes a
layout, and writes the view for you.

<Steps>
  <Step title="Open the annotator view">
    Create a queue, or open one and click **Edit**. In the **Annotator view** card, click
    **Preview & edit with Ollie**.
  </Step>
  <Step title="Describe what annotators need">
    Ollie opens next to a live preview of the view. Tell it what to show, hide or highlight, or pick one of its
    suggestions. Each change shows up in the preview right away.
  </Step>
  <Step title="Check it on real items">
    Use the arrows above the preview to step through sample items.
  </Step>
  <Step title="Save">
    Click **Save changes** (or **Create queue** for a new queue). Annotators see the new view for every item.
  </Step>
</Steps>

- **Fix with Ollie**: when the view fails on a sample item, the preview offers to fix it.

### Build it with your coding agent

No Ollie in your workspace, or out of Ollie credits? Build the view with your own coding agent instead. Connect it
to the [Opik MCP server](/mcp-server) and ask for the view in plain words, for example:

```text wordWrap
Build a custom annotator view for the "Itinerary review" queue in the Travel Assistant project.
Show the plan next to the request and hide the judge scores until the annotator reveals them.
```

The agent reads the queue and its items, writes the view, saves it to the queue, and returns the queue link so
you can check it. Ask it for changes the same way, or to remove the view.

## Managing Queues programmatically

You can create and manage annotation queues programmatically using the Python or TypeScript SDK. This is useful for automating the process of adding items to queues based on specific criteria.

### Creating an Annotation Queue

<Tabs>
    <Tab value="Python" title="Python">

### Creating a Traces Annotation Queue

```python wordWrap
import opik

client = opik.Opik()

# Create a traces annotation queue
queue = client.create_traces_annotation_queue(
    name="High Priority Traces",
    description="Traces that need review",
    instructions="Check for accuracy and completeness",
    feedback_definition_names=["relevance", "accuracy"]
)

print(f"Created queue: {queue.name} (ID: {queue.id})")
```

    </Tab>
    <Tab value="TypeScript" title="TypeScript">

```typescript wordWrap
import { Opik } from "opik";

const client = new Opik();

// Create a trace annotation queue
const queue = await client.createTracesAnnotationQueue({
  name: "High Priority Traces",
  description: "Traces that need review",
  instructions: "Check for accuracy and completeness",
  feedbackDefinitionNames: ["relevance", "accuracy"],
});

console.log(`Created queue: ${queue.name} (ID: ${queue.id})`);
```

### Adding Traces to a Queue

<Tabs>
    <Tab value="Python" title="Python">

```python wordWrap
import opik

client = opik.Opik()

# Get an existing traces queue
queue = client.get_traces_annotation_queue("queue-id")

# Search for traces and add them to the queue
traces = client.search_traces(
  project_name="my-project",
  filter_string='feedback_scores.user_frustration > 0.5'
)
queue.add_traces(traces)

# For a single trace, wrap it in a list
single_trace = client.get_trace_content("trace-id")
queue.add_traces([single_trace])
```

    </Tab>
    <Tab value="TypeScript" title="TypeScript">

```typescript wordWrap
import { Opik } from "opik";

const client = new Opik();

// Get an existing traces queue
const queue = await client.getTracesAnnotationQueue("queue-id");

// Search for traces and add them to the queue
const traces = await client.searchTraces({
  projectName: "my-project",
  filterString: 'feedback_scores.user_frustration > 0.5',
});
await queue.addTraces(traces);

// For a single trace, wrap it in an array
const singleTraceResponse = await client.api.traces.getTraceById("trace-id");
await queue.addTraces([singleTraceResponse.data]);
```

### Fetching Items from a Queue

Use `get_items()` to retrieve all the traces (or threads, for a thread queue) currently in a queue. The items are scoped to the queue's project.

<Tabs>
    <Tab value="Python" title="Python">

```python wordWrap
import opik

client = opik.Opik()

# Get an existing traces queue
queue = client.get_traces_annotation_queue("queue-id")

# Fetch all traces currently in the queue
traces = queue.get_items()

for trace in traces:
    print(trace.id, trace.name)

# For a threads queue, get_items() returns the threads instead
thread_queue = client.get_threads_annotation_queue("thread-queue-id")
threads = thread_queue.get_items()
```

    </Tab>
    <Tab value="TypeScript" title="TypeScript">

```typescript wordWrap
import { Opik } from "opik";

const client = new Opik();

// Get an existing traces queue
const queue = await client.getTracesAnnotationQueue("queue-id");

// Fetch all traces currently in the queue
const traces = await queue.getItems();

for (const trace of traces) {
  console.log(trace.id, trace.name);
}

// For a threads queue, getItems() returns the threads instead
const threadQueue = await client.getThreadsAnnotationQueue("thread-queue-id");
const threads = await threadQueue.getItems();
```

### Working with Thread Queues

<Tabs>
    <Tab value="Python" title="Python">

```python wordWrap
import opik

client = opik.Opik()

# Create a threads annotation queue
thread_queue = client.create_threads_annotation_queue(
    name="Thread Review Queue",
    description="Threads needing review"
)

# Get threads and add them to the queue
threads_client = client.get_threads_client()
important_threads = threads_client.search_threads(
```

### Updating and Deleting Queues

<Tabs>
    <Tab value="Python" title="Python">

```python wordWrap
import opik

client = opik.Opik()

# Get an existing traces queue
queue = client.get_traces_annotation_queue("queue-id")

# Update queue properties
queue.update(
    description="Traces that need a thorough review",
    instructions="Check the conversation tone"
)

# Remove traces from the queue
short_traces = client.search_traces(
  project_name="my-project",
  filter_string='duration < 10'
)
queue.remove_traces(short_traces)

# Delete the queue
queue.delete()
```

    </Tab>
    <Tab value="TypeScript" title="TypeScript">

```typescript wordWrap
import { Opik } from "opik";

const client = new Opik();

// Get an existing traces queue

});

  projectName: "my-project",
  filterString: "duration < 10",

await queue.removeTraces(shortTraces);

// Delete the queue
await queue.delete();
```

```python wordWrap
import opik

client = opik.Opik()
```
